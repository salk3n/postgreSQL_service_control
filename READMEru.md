# Управление службой PostgreSQL

> GUI-замена `pgadmin_service_control.bat` — управляйте службой PostgreSQL
> в Windows, следите за её реальным состоянием и запускайте pgAdmin из одного окна.

## Возможности

| Функция | Описание |
|---|---|
| Управление службой | Пуск / Стоп / Перезапуск через `net` + `sc` с проверкой реального результата после каждой операции |
| Проверка здоровья | Без учётных данных, по протоколу PostgreSQL — обнаруживает «запущенный, но зависший» postmaster, который `sc query` не видит |
| Системный трей | Цветной значок (зелёный/жёлтый/красный), операции в один клик, переключатель уведомлений |
| Уведомления | О результатах операций и изменениях состояния |
| Журнал | Ротируемый файловый журнал всех операций — всегда на английском |
| Конфигурация | Один `config.json`, переносимый, редактируется из приложения |
| Языки | Русский и английский |
| Тёмная тема | Светлая / тёмная, переключается в приложении |

### Состояния здоровья

Приложение сверяет состояние службы Windows с TCP-проверкой протокола
PostgreSQL (пакет `SSLRequest` — **учётные данные нигде не хранятся**):

| Состояние SCM | Проверка | Здоровье | Что означает |
|---|---|---|---|
| ЗАПУЩЕНА | отвечает | 🟢 ИСПРАВНА | Штатный режим |
| ЗАПУЩЕНА | молчит | 🟠 ЗАПУЩЕНА / НЕТ ОТВЕТА | Зависший postmaster, неверный порт или файрвол |
| ОСТАНОВЛЕНА | молчит | 🔴 ОСТАНОВЛЕНА | Служба не работает |
| ОСТАНОВЛЕНА | отвечает | 🟠 ОСТАНОВЛЕНА / ПОРТ ЗАНЯТ | Порт занят другим процессом |

## Требования

- Windows 10 / 11
- PostgreSQL, установленный как служба Windows
- Python 3.9+ (только при запуске из исходников)

Опционально (для значка в трее и уведомлений):

```
pip install pystray Pillow
```

Без них приложение работает — трей и уведомления отключаются с предупреждением.

## Установка

### Вариант A — готовый exe (GitHub Release)

1. Скачайте `PgAdminServiceControl.exe` из [последнего релиза](../../releases).
2. Поместите в любую папку. При первом запуске рядом создаются `config.json`
   и `service_control.log` (или в `%LOCALAPPDATA%\PgAdminServiceControl\`,
   если папка недоступна для записи).
3. Для управления службой: правая кнопка → **Запуск от имени администратора**.

### Вариант B — из исходников

```bat
git clone https://github.com/salk3n/PgAdminServiceControl.git
cd PgAdminServiceControl
python pgadmin_service_control.py
```

### Сборка собственного exe

```bat
build.bat
```

Создаёт `dist\PgAdminServiceControl.exe` (PyInstaller, без консоли).
Положите `icon.ico` рядом с `build.bat`, чтобы задать свою иконку.

> **Примечание:** неподписанные exe от PyInstaller могут вызывать предупреждения
> SmartScreen / антивирусов при первом запуске. Это нормально для неподписанных
> программ, управляющих службами.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Alt+1` | Запустить службу |
| `Alt+2` | Остановить службу |
| `Alt+3` | Перезапустить службу |
| `Alt+4` | Обновить статус |
| `Alt+5` | Открыть pgAdmin 4 |
| `Alt+C` | Настройки — работает и как `Alt+С` на русской раскладке |
| `Esc` | Выход (сворачивает в трей, если трей включён) |

Клавиши работают независимо от фокуса и намеренно игнорируются, пока открыт
диалог настроек.

## Конфигурация

`config.json` создаётся автоматически рядом с exe:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `service_name` | `postgresql-x64-18` | Имя службы. Кнопка **Поиск** в настройках найдёт установленные службы PostgreSQL |
| `pgadmin_path` | *(путь PG 18)* | Путь к `pgAdmin4.exe`; проверяется при каждом запуске |
| `host` / `port` | `127.0.0.1` / `5432` | Цель проверки здоровья — должны совпадать с `listen_addresses` / `port` в `postgresql.conf` |
| `probe_enabled` | `true` | Включить проверку по протоколу |
| `probe_timeout_seconds` | `3` | Тайм-аут проверки |
| `auto_refresh` | `true` | Фоновый опрос |
| `refresh_interval_seconds` | `5` | Интервал опроса |
| `operation_timeout_seconds` | `300` | Тайм-аут операций. Большой по умолчанию: финальный checkpoint при остановке на продакшене может занимать минуты |
| `theme` | `light` | `light` / `dark` |
| `language` | `en` | `en` / `ru` — применяется после перезапуска |
| `tray_enabled` | `true` | Значок в трее |
| `minimize_to_tray` | `true` | Сворачивать в трей |
| `toast_enabled` | `true` | Всплывающие уведомления |
| `log_enabled` | `true` | Файловый журнал |
| `log_max_mb` / `log_backups` | `2` / `5` | Ротация журнала |
| `advanced_enabled` | `false` | **Разблокирует операции записи в SCM** (тип запуска, восстановление) — см. ниже |

## Безопасность на продакшене

Инструмент работает с реальными базами данных, поэтому настроен консервативно:

- **Операции записи в SCM** (тип запуска, настройка восстановления)
  **заблокированы**, пока вы вручную не зададите `"advanced_enabled": true` в
  `config.json`. Из интерфейса флаг не переключается; *Сброс по умолчанию*
  блокирует его обратно. Это защита от случайных изменений, а не контроль доступа.
- **Никаких учётных данных.** Проверка здоровья использует
  неаутентифицированный обмен `SSLRequest`. В `config.json` не должно быть секретов.
- **Нет встроенного сторожа.** Надзор — задача самой Windows: кнопка
  *Настроить восстановление SCM* задаёт нативное восстановление службы
  (перезапуск через 5 с / 15 с / 60 с), работающее без этого приложения.
- **Один экземпляр.** Именованный мьютекс исключает двойной запуск.

## Языки

- **Настройки → Поведение → Язык** или ключ `"language"` в `config.json`.
  Применяется после перезапуска.
- **Файловый журнал всегда на английском** — специально, чтобы его можно было
  искать по ключевым словам.
- Сырой вывод `sc.exe` / `net.exe` показывается на языке Windows и переводу
  не поддаётся.

## Не приходят уведомления?

1. **Должен работать значок в трее** — без него в Windows нет канала
   уведомлений. Нужны `pystray` + `Pillow` и `tray_enabled: true`.
2. Выполните Пуск/Стоп — операции уведомляют и об успехе, и об ошибке.
3. Проверьте *Параметры → Система → Уведомления* для этого приложения;
   убедитесь, что режим «Не беспокоить» выключен.
4. Загляните в область переполнения трея (`^`) — Windows прячет новые значки там.
5. В `service_control.log` найдите `NOTIFY` — каждое решение об уведомлении
   записывается (`Toast dispatched` / `Toast skipped: ...` / `icon.notify failed`).

## Что делать при 🟠 ЗАПУЩЕНА / НЕТ ОТВЕТА

SCM сообщает, что служба запущена, но протокол PostgreSQL не отвечает:

1. Проверьте последний файл в `C:\Program Files\PostgreSQL\18\data\log\`
   (нужны права администратора) на повторяющиеся `FATAL` / `PANIC`.
2. Проверьте свободное место на диске — при заполненном диске запись WAL
   останавливается, хотя postmaster жив: это ровно данное состояние.
3. Убедитесь, что `host` / `port` в `config.json` совпадают с `postgresql.conf`.
4. Только после этого рассматривайте контролируемый перезапуск.

Каждая операция фиксируется в `service_control.log` с меткой времени и
уровнем прав — сверяйтесь с журналом до и после инцидентов.

## Осознанные ограничения (не будет добавлено)

- Учётные данные БД — никогда
- Выполнение запросов / просмотр БД (это задача pgAdmin)
- Встроенные планировщик или сторож (используйте восстановление SCM / Планировщик задач)
- Автообновление (автообновление с правами администратора — канал эскалации привилегий)
- Принудительное завершение postmaster (семантика сбоя + риск при восстановлении WAL)
